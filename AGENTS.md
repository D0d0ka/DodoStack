# DodoStack

- Run the workspace and its services with `.venv/bin/python server.py` from the repository root. Install dependencies with `python -m pip install -r requirements.txt`.
- Use the shared DodoStack identity in `dodo/auth.py`. Require sign-in on service routes, check ownership with the shared account ID, and validate CSRF tokens on state-changing browser requests.
- Keep each service in `subsites/`. Register it in `SERVICE_MODULES` and `BRAND_FILES` in `server.py` and add its name and description in `dodo/pages.py`. Link workspace cards directly to their services.
- Keep local data and signing keys out of Git. Services initialize their databases from the current schema. Run destructive data operations only when explicitly requested, and use isolated data for verification.
- DodoKey encrypts and decrypts vault entries in the browser. Keep vault passwords, derived keys, and unencrypted entries out of requests, logs, and persistent browser storage. Keep scripts and styles local to DodoKey.
- Verify changes through the normal workspace and service routes. Check signed-out access and account isolation when editing authentication or personal data.
- Use .venv as python environment.
- Always when you learn something new about this project that would help in developing it later write it into this file.
- Use a referrer policy such as `strict-origin` for native POST forms. With `no-referrer`, browsers send `Origin: null` and the shared origin check rejects the form.
- An HTTP reverse proxy should preserve the browser's Host header. Register each proxy workspace as `host:port` in `DODO_WORKSPACE_HOSTS` when the browser port differs from `DODO_PORT`. Workspace and service redirects use the configured browser port.
- In `DODO_WORKSPACE_HOSTS`, `host[:port]=service-domain` also registers the bare service domain as a workspace on that browser-facing port. Services on that domain use its workspace for sign-in. Entries sharing a service domain must agree on the port.
- `DODO_DEBUG` enables detailed server diagnostics. Use `X-Request-ID` to match a response to its stderr logs. Keep request payloads, query values, credentials, and exception messages out of diagnostics. Route browser error responses through `dodo/pages.py` or the service's error handlers and preserve API response formats and HTTP error headers.
- `DODO_HTTPS=true` enables direct TLS with `DODO_TLS_CERT_FILE` and `DODO_TLS_KEY_FILE`. It also selects HTTPS URLs, origin checks, and `__Host-` secure cookies. Restart after certificate renewal. The bundled listener uses Python's `ThreadingHTTPServer`, which Python advises against exposing in production.
- Shared sign-in tickets are tied to a service host and browser cookie, expire after two minutes, and are redeemed once in the shared account database. Keep `/_auth/callback` query strings out of proxy access logs. Workspace and service mutations require a form CSRF token or `X-CSRFToken`, depending on the framework.
- Doodle connects to the public IP address it verified for each crawl request and redirect. HTTPS certificate verification and the Host header still use the original hostname.
- The workspace shows service names and descriptions to signed-out visitors in both public and private mode. Only signed-in visitors get clickable service cards.
- Prefix a `DODO_WORKSPACE_HOSTS` entry with `https://` for a TLS-terminating proxy. It sets the browser-facing scheme and default port 443 independently of the local listener. A registered `*.trycloudflare.com` entry automatically uses public HTTPS and serves the workspace only. Replace it when the tunnel hostname changes. Use a named tunnel covering each service hostname for service links. Generic unknown-host errors use same-origin assets.
- The shared account database stores DodoMail and writes the welcome message in the same transaction as registration. Keep birth dates and real names out of shared session claims and service profiles.
- Mail delivery uses the authenticated server-side service context and a shared assertion. Calendar invitation creation, cancellation and responses use one SQLite transaction across the calendar and account databases via `ATTACH DATABASE`. Keep both databases on disk with rollback journaling for atomic commits across files.
- DodoTodo renders its live pages in `subsites/todo/app.py`. Its SQLite `user_version` migration preserves existing tasks as Inbox entries. Child tasks inherit the parent’s project and section. Recurring tasks advance past the current day on completion and retain their original calendar-day anchor.
- Signup accepts separate first and last name fields and stores their combined value in `users.real_name`. Sign-in accepts the shared username, account email, or DodoMail address.
- The workspace serves assets through `dodo/framework.py`. Serve scripts as `text/javascript` because the server sets `X-Content-Type-Options: nosniff`.
- When adding a service with a supplied logo, copy the logo into that service’s directory and register the copied file in `BRAND_FILES`.
- DodoMail stores personal messages in `user_mail` in the account database. A null recipient identifies the reserved `support@dmail` inbox and a null sender identifies an admin reply from Support. The Support tab is mounted on the workspace admin host.
- Service navigation uses the active identity’s `workspace_url` for the DodoStack home link. Doodle builds direct links from enabled services, using workspace names and descriptions plus search aliases defined in `subsites/doodle/app.py`.
- DodoKey uses native Web Crypto when available and serves a local Noble fallback on HTTP. Both paths must read and write the same v1 format with PBKDF2-SHA-256 (600,000 iterations), AES-256-GCM and the same associated data. Use `crypto.getRandomValues` for randomness on both paths.
- The shared account dropdown uses same-origin `/static/account-menu.css`. Workspace menus use `/logout` and workspace CSRF. Service menus use `/_auth/logout` with a CSRF token tied to the service session. DodoTV uses its existing dropdown and logout form.
- Returning an account to approval pending revokes its workspace and service sessions. Account deletion removes the shared account and its DodoMail rows in one transaction. Separate service stores still key their records by the old account ID. Keep shared account IDs non-reusable and preserve at least one approved administrator.
