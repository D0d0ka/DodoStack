# DodoStack

- Run the workspace and its services with `.venv/bin/python server.py` from the repository root. Install dependencies with `python -m pip install -r requirements.txt`.
- Use the shared DodoStack identity in `dodo/auth.py`. Require sign-in on service routes, check ownership with the shared account ID, and validate CSRF tokens on state-changing browser requests.
- Keep each service in `subsites/<package>/` with a `service.json` manifest. `dodo/services.py` scans immediate subdirectories at process startup without importing apps; `server.py` starts each declared `entrypoint`. Names, descriptions, logo paths, search aliases, display order, admin permission labels and optional CLI commands come from manifests. Link workspace cards directly to their services. No central service list needs editing.
- Keep local data and signing keys out of Git. Services initialize their databases from the current schema. Run destructive data operations only when explicitly requested, and use isolated data for verification.
- DodoKey encrypts and decrypts vault entries in the browser. Keep vault passwords, derived keys, and unencrypted entries out of requests, logs, and persistent browser storage. Keep scripts and styles local to DodoKey.
- Verify changes through the normal workspace and service routes. Check signed-out access and account isolation when editing authentication or personal data.
- Use .venv as python environment.
- DodoTV movie and episode forms import individual YouTube URLs through `app/utils/youtube.py` using yt-dlp and FFmpeg. Imports use temporary storage, validate files through the normal media helpers, and track new files for rollback. Replacing a video through YouTube also replaces its subtitles; manually added captions take priority over automatic captions in the same language.
- Run the isolated DodoTV import regressions with `.venv/bin/python -m unittest discover -s tests -p test_dodotv_youtube.py -v`; they use temporary databases and stub YouTube downloads while validating real media with FFmpeg/FFprobe.
- `DODO_LOCALHOST_ENABLED` defaults to `true`. Set it to `false` to disable workspace routes for localhost, 127.0.0.1 and 0.0.0.0 plus service routes under `.localhost`; configure `DODO_WORKSPACE_HOSTS` for access instead. `DODO_HOST` independently controls the listener, so local reverse proxies can still connect. Restart after changes.
- Always when you learn something new about this project that would help in developing it later write it into this file.
- Use a referrer policy such as `strict-origin` for native POST forms. With `no-referrer`, browsers send `Origin: null` and the shared origin check rejects the form.
- An HTTP reverse proxy should preserve the browser's Host header. Register each proxy workspace as `host:port` in `DODO_WORKSPACE_HOSTS` when the browser port differs from `DODO_PORT`. Workspace and service redirects use the configured browser port.
- In `DODO_WORKSPACE_HOSTS`, `host[:port]=service-domain` also registers the bare service domain as a workspace on that browser-facing port. Services on that domain use its workspace for sign-in. Entries sharing a service domain must agree on the port.
- `DODO_DEBUG` enables detailed server diagnostics. Use `X-Request-ID` to match a response to its stderr logs. Keep request payloads, query values, credentials, and exception messages out of diagnostics. Route browser error responses through `dodo/pages.py` or the service's error handlers and preserve API response formats and HTTP error headers.
- `DODO_HTTPS=true` enables direct TLS with `DODO_TLS_CERT_FILE` and `DODO_TLS_KEY_FILE`. It also selects HTTPS URLs, origin checks, and `__Host-` secure cookies. Restart after certificate renewal. The bundled listener uses Python's `ThreadingHTTPServer`, which Python advises against exposing in production.
- Shared sign-in tickets are tied to a service host and browser cookie, expire after two minutes, and are redeemed once in the shared account database. Keep `/_auth/callback` query strings out of proxy access logs. Workspace and service mutations require a form CSRF token or `X-CSRFToken`, depending on the framework.
- Doodle connects to the public IP address it verified for each crawl request and redirect. HTTPS certificate verification and the Host header still use the original hostname.
- The workspace shows clickable service cards to signed-out visitors in both public and private mode; these link to `/login`. Signed-in visitors get direct service links when service hostnames are configured.
- Prefix a `DODO_WORKSPACE_HOSTS` entry with `https://` for a TLS-terminating proxy. It sets the browser-facing scheme and default port 443 independently of the local listener. A registered `*.trycloudflare.com` entry automatically uses public HTTPS and serves the workspace only. Replace it when the tunnel hostname changes. Use a named tunnel covering each service hostname for service links. Generic unknown-host errors use same-origin assets.
- The shared account database stores DodoMail and writes the welcome message in the same transaction as registration. Keep birth dates and real names out of shared session claims and service profiles.
- Mail delivery uses the authenticated server-side service context and a shared assertion. Calendar invitation creation, cancellation and responses use one SQLite transaction across the calendar and account databases via `ATTACH DATABASE`. Keep both databases on disk with rollback journaling for atomic commits across files.
- DodoTodo renders its live pages in `subsites/todo/app.py`. Its SQLite `user_version` migration preserves existing tasks as Inbox entries. Child tasks inherit the parent’s project and section. Recurring tasks advance past the current day on completion and retain their original calendar-day anchor.
- Signup accepts separate first and last name fields and stores their combined value in `users.real_name`. Sign-in accepts the shared username, account email, or DodoMail address.
- The workspace serves assets through `dodo/framework.py`. Serve scripts as `text/javascript` because the server sets `X-Content-Type-Options: nosniff`.
- When adding a service with a supplied logo, copy the PNG into that service’s directory and set its relative path in the manifest's `logo` field.
- DodoMail stores personal messages in `user_mail` in the account database. A null recipient identifies the reserved `support@dmail` inbox and a null sender identifies an admin reply from Support. The Support tab is mounted on the workspace admin host.
- Service navigation uses the active identity’s `workspace_url` for the DodoStack home link. Doodle builds direct links from discovered services using manifest names, descriptions and `search_aliases`.
- DodoKey uses native Web Crypto when available and serves a local Noble fallback on HTTP. Both paths must read and write the same v1 format with PBKDF2-SHA-256 (600,000 iterations), AES-256-GCM and the same associated data. Use `crypto.getRandomValues` for randomness on both paths.
- The shared account dropdown uses same-origin `/static/account-menu.css`. Workspace menus use `/logout` and workspace CSRF. Service menus use `/_auth/logout` with a CSRF token tied to the service session. DodoTV uses its existing dropdown and logout form.
- Returning an account to approval pending revokes its workspace and service sessions. Account deletion removes the shared account and its DodoMail rows in one transaction. Separate service stores still key their records by the old account ID. Keep shared account IDs non-reusable and preserve at least one approved owner.
- DodoBook’s mobile layout (up to 820px) opens on Feed with Chat to its left and Friends to its right. Keep the breakpoint in its template script and `subsites/dodobook/static/feed-layout.css` aligned. Restoring a saved chat must leave Feed active, and mobile chat polling should fetch messages only while Chat is visible.
- New DodoBook profiles must complete the welcome version of `/profile` (local display name and optional icon) before using social pages or APIs. `user.profile_completed` is stored in the service database; the additive migration marks existing profiles complete. Shared account names are unchanged, and workspace administration bypasses setup.
- Run DodoBook's isolated setup and account-isolation checks with `.venv/bin/python -m unittest discover -s checks -p test_dodobook_onboarding.py -v`.

- Doodle hidden domains include their subdomains and are visible to owners and administrators with the Doodle permission on both service and workspace admin search routes. Filter media by both its page and asset domains. Never expose the hidden-domain filter list in ordinary search responses.
- The admin account listing deliberately excludes real email addresses from both its SQL projection and rendered page. Keep the account owner's email settings separate from admin listings.
- Run the isolated HTTP privacy regressions with `.venv/bin/python -m unittest discover -s tests -v`. Doodle deduplicates identical page content, so use distinct content when seeding multiple search-result fixtures.

- Shared administration uses `is_owner` plus explicit `admin_permissions` in `dodo/auth.py`. Only approved owners can assign roles and permissions. Check `can_admin(user, service)` for service privileges, including normal service views; never use the global `is_admin` flag for service authorization. `ADMIN_PERMISSIONS` is derived from manifest `admin_label` values plus the core accounts permission; services exposing admin tabs must declare `admin_label`.
- Shared mailbox schema and trusted delivery live in `dodo/mail.py`, so accounts and the calendar do not import or start the DodoMail app. `subsites/dodomail/delivery.py` preserves the existing delivery import API. DodoMail loads its optional calendar integration only when responding to an invitation.
- Run isolated manifest validation and add/remove/startup regressions with `.venv/bin/python -m unittest discover -s tests -p test_service_discovery.py -v`. They copy source into temporary storage and never initialize personal databases.
- Account-management admins can manage members only; owners manage privileged accounts. Keep at least one approved owner. The one-time legacy migration promotes the oldest approved administrator to owner and preserves other admins’ existing permissions. On a fresh installation, trusted `set-admin` bootstraps the first owner. Roles and permissions are read from the account database on every request, so scope changes apply to existing sessions immediately.
- Use `.venv/bin/python server.py set-owner USERNAME` to grant an existing shared account the owner role from the trusted local CLI. It also approves the account, preserves other owners, and can recover ownership without an existing owner session. Unknown usernames fail without creating an account.
- Shared account-store operations must use `with closing(self.connect()) as db, db:`: SQLite's connection context manager commits or rolls back but does not close the connection. Authentication opens several connections per service request.
- Doodle ranks substring candidates with SQL and Python; its search does not use the optional FTS table. Do not try loading SQLite extensions on each connection. Snippet window scoring must avoid quadratic scans and preserve first-window tie selection. Media results reuse each source page's score and snippet within a search.
- Doodle's crawler and search share YouTube validation in `subsites/doodle/urls.py`. Always generate iframe URLs from a validated video ID on `www.youtube-nocookie.com`, including for previously indexed assets; never trust a stored iframe URL or a hostname substring.
- Run `.venv/bin/python -m unittest discover -s checks -v` for the isolated Doodle security/performance and shared account connection checks. The HTTP check starts a temporary loopback server from a temporary source copy; it never opens personal databases or calls external search providers. Doodle search arguments are limited to 512 characters; social search uses a shared six-worker pool with at most four admitted searches.
- DodoBook feed extras and unread chat counts are fetched in batches; keep their query count independent of the number of posts and friends. Its startup adds indexes to existing tables explicitly, since SQLAlchemy `create_all()` does not add indexes to tables that already exist. Preserve dynamic relationships used by write routes.
- DodoTV browse sorts compact metadata with Python's existing Unicode ordering and stable ties, then loads complete models only for the selected page. Preserve mixed movie/show order, filters and pagination when optimizing it.
- Routed web responses default to `Cache-Control: no-store`; explicit file/media caching headers are preserved. Shared sign-in must run password verification for missing accounts too, to reduce identifier enumeration through timing. Email lookups use an index on `lower(email)`.
- DodoMail inbox projections omit message bodies; full messages remain behind ownership checks. Unread inbox counts have partial recipient indexes. The calendar should not enumerate holiday providers when no holiday country is enabled.
- `checks/test_remaining_services.py` runs the remaining services' HTTP security/performance checks in a temporary workspace, including DodoKey vault revision conflicts, Todo/Calendar/Mail isolation, DodoBook query counts and DodoTV page loading. It needs permission to bind a loopback port; no external network calls or personal databases are used.
